# OpsLens panel in EcoStruxure Operator Terminal Expert

The project does not include a native EOTE project file. The screenshot shows an unsaved `NewMain` screen, so this guide adds the live OpsLens panel to that screen without duplicating the RAG, alarm, evidence, or SOP logic in EOTE.

## Live panel using the EOTE Web Browser part

For the local editor simulator on the same Edge PC:

1. Start Qdrant, the FastAPI backend, and the OpsLens HMI as described in the repository README.
2. In EOTE, open `NewMain` and drag the **Web Browser** part from the Tool Chest onto the central canvas.
3. Size it to the available display area. For a 16:9 target, use a 1280 × 720 screen or the closest supported target resolution.
4. In the Web Browser part's properties, set its URL to `http://127.0.0.1:5173/`.
5. Run the EOTE simulator. The embedded page gets telemetry, event stories, evidence, matched SOPs, and SOP procedure content from OpsLens; those remain generated by the existing backend.

Schneider documents a Web Browser part in EOTE and SVG compatibility. The live page is preferable for runtime values; the SVG below is only a visual reference and contains a static Pump-02 demo snapshot.

## Separate Harmony panel and Edge PC

When EOTE Runtime runs on a different device from OpsLens, `localhost` refers to the HMI device. Host the built HMI on the OpsLens Edge PC and use its reachable LAN address in the EOTE Web Browser URL, for example `http://192.168.1.50:5173/`. Build the frontend with the backend URL set to the Edge PC:

```powershell
cd hmi_ui
$env:VITE_API_BASE_URL = 'http://192.168.1.50:8000/api'
npm run build
```

Replace `192.168.1.50` with the Edge PC's actual address. Configure the web server and local network firewall to allow the HMI to reach ports 5173 and 8000 on that Edge PC. Qdrant stays local to the backend and does not need to be exposed to the HMI.

## Static visual reference

The 1280 × 720 layout is [ecostruxure-opslens-panel.svg](../hmi_ui/public/ecostruxure-opslens-panel.svg). To view it in EOTE, select the target Screen, drag an Image shape from the Tool Chest, then choose the SVG in its Shape/Image properties. Schneider's image workflow is to select a screen, drag an Image object from the Tool Chest, and set its image in Properties.

The reference shows:

- Pump-02 critical alarm `ALM-P02-HP`.
- Valve, flow, current, and pressure telemetry.
- The time-ordered causal chain and evidence summary.
- The Qdrant matched SOP and raw semantic similarity.
- A read-only advisory footer with no PLC or actuator command controls.

The actual live HMI gets its score, SOP, and steps from FastAPI/Qdrant; do not bind the static snapshot values as live signals. Keep the EOTE screen read-only with respect to PLCs and actuators.
